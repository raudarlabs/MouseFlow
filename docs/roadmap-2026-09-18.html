Next, in order

5 · A door to Connections in P1

Why. Four screens, and none of them is the one a new person needs on day one. The "no agent" notice already says Open Connections — naming a place the menu does not have.

How. A nav row of its own, or a button inside that notice. One line either way.

Done when. Nothing has to be found in a dialog before the first run.

6 · Create as a list of threads

Why. The owner's shape, and most of it exists: the goal is stored, relaunch() already moves it into the composer, EarlierPanel already lists past runs.

How. Move the list left; a row opens its goal and its attachments; two actions — Run again and Change and run. Not conversation state: that is a different project (see proposals).

Done when. A past task is one click from running again, without going through Logs.

7 · Cut Skills into Library (P2) and Runs (P1)

Why. The last screen still marked both, and the only thing between here and two coherent products.

How. Split the view; SkillWizard stays one component, imported by whichever product shows it.

Done when. Neither half uses the other's vocabulary.

8 · The P2 dashboard asks ?half=did

Why. Was a page split; is now one query parameter, because the Dashboard moved to P2 whole.

How. One line in InsightsView, using the HALF constant that is already named there.

Done when. The dashboard runs no query against user_run.

9 · Restore /docs and /chat as first-class P2 routes

Why. A document is P2's output and is reachable only through the Gallery's second shelf.

How. Undo two redirects; both screens exist already.

Done when. A document opens without going through the Gallery.

10 · Partition LIMITS

Why. Two products, one budget: a chat turn and a run share a ceiling today.

How. A partition of keys in api/_spend.mjs. No schema change.

Done when. One product's spend cannot exhaust the other's.

11 · MCP profiles — P1's 7, P2's 7, the shared 4

Why. A P2 connector seeing mouseflow_run is a product leak. The tool list is one array, so it is cheap.

How. Subset the array by profile.

Done when. A P2 connector never sees mouseflow_run.

12 · --record-only agent, both halves

Why. P2's pitch is "it only watches", and today that is a claim rather than a flag.

How. One flag hung on Input.refusal(); the C# compiled for real, not read.

Done when. A record-only agent refuses every injection action, and says so in words.

13 · Transcription route

Why. Dictation quality was the ask, and the choice reverses a promise the code makes — so the route and the sentence saying where the audio goes ship together.

How. Copy the shape of api/claude.js: key on the server, upload capped, its own LIMITS key.

Done when. A goal can be dictated, and the UI says where the audio goes before the microphone is armed.

14 · One messenger channel (Telegram), with the pairing rule

Why. Cheaper than a PWA and brings push for free. The queue already does the hard half — a phone is one more thing that inserts a row.

How. One ingress that turns a message into a run_queue row and posts the outcome back. Unknown senders are paired, not served, until approved by code — lifted from OpenClaw, because knowing a bot's handle should not be enough to queue work on somebody's computer.

Done when. A goal sent from a phone runs on the desk, and an unapproved sender cannot queue anything.

15 · Split the docs set into two indexes

Why. Each product's documentation should read as one product's.

How. Two indexes over the existing pages.

Done when. agent/check-promises.mjs still green.

Proposals — worth doing, nobody has asked yet

What Why it is below the line
Threads with conversation state A second kind of memory beside app_memory, and a thread_id answered again in the extension and the desktop driver. Wanted only if step 6 shows people asking follow-ups
The PWA Still right for a phone that is not a chat app. Behind the messenger because that costs a bot token and this costs a mobile layout
Packaging the Windows agent on .NET 10 Technically settled: yes, .NET 10, Windows first. Commercially not — nothing measured says the installer is what loses people. Ask one buyer before buying a certificate
Attachments with their own field Today an attached file is part of the goal, capped at 4000 characters because that is what the queue path stores. A real field would cross the queue, three loops and the extension — worth it when somebody hits the cap for a real reason
Replacing @insightis/ui 228 vendored files from another Devart product. The name never reaches a built bundle and source maps are not published, so the exposure is the repository and the Sentry project — not the client. Only needed if sources are ever handed over
Housekeeping db/022_queue_machine.sql's header still says "НЕ ПРИМЕНЕНА"; it was applied on 11 September

Decisions that made the plan smaller

  • The Dashboard, Gallery and Teams moved to the second product whole — so the dashboard split became one query parameter instead of splitting a 2 331-line view. Step 3 is what made that possible.
  • The first product runs on the local agent alone — no executor choice left to design around.
  • The Gallery question is answered (it was open question §11.2): it is the second product's.

Still only the owner can answer

  1. The product names — Do it for me / Make it reusable are working titles, in one place, one edit to change.
  2. Which messenger first, and whether a chat account may drive a desktop at all.
  3. Do threads carry conversation state?
  4. Does Connections stay in P1's menu forever, or only until the agent is installed?
  5. Does P2 ship a record-only agent by default?
  6. Does dictation keep an on-device fallback, or simply say the audio goes to OpenAI?
  7. When to pay for packaging and a code-signing certificate.
